# Resend Setup Guide

TenXPros launch email is transactional only: application, admission, payment placeholder, enrollment, review, support, and certification messages.

## 1. Domain Authentication

1. Add the sending domain in Resend.
2. Add the DNS records Resend provides.
3. Wait for Resend to show the domain as verified.
4. Do not use a production sender until verification is complete.

Resend will provide the exact DNS records in its dashboard. Copy the generated values exactly from Resend into the DNS provider. Do not invent or hand-type approximate DNS values.

Expected record categories:

- DKIM records, usually one or more `TXT` or `CNAME` records generated by Resend.
- SPF/update guidance, usually a `TXT` record or an include mechanism depending on the existing domain setup.
- Domain verification record, if Resend provides one separately.
- Optional return-path or bounce handling record if Resend requires it for the account/domain.

## 2. SPF, DKIM, And DMARC

Before launch, confirm:

- SPF includes the provider records Resend requires.
- DKIM records are present and verified.
- DMARC exists for the domain.
- The sender domain aligns with the brand domain where possible.

## 3. EMAIL_FROM Guidance

Use a verified sender:

```bash
EMAIL_FROM="TenXPros <hello@tenxpros.com>"
```

Avoid personal addresses for production transactional email. Keep the display name stable so applicants and participants recognize TenXPros messages.

## 4. Environment Variables

Production:

```bash
EMAIL_PROVIDER=resend
RESEND_API_KEY=replace-with-production-resend-key
EMAIL_FROM="TenXPros <hello@tenxpros.com>"
```

Local/dev may use:

```bash
EMAIL_PROVIDER=console
EMAIL_FROM="TenXPros <hello@tenxpros.test>"
```

## 5. How To Test Email Sending

1. Configure production-like env values in a staging or controlled production environment.
2. Submit a test application.
3. Accept the application as admin.
4. Confirm the accepted/payment-link email is delivered.
5. Mark payment received and enroll.
6. Confirm the welcome/password setup email is delivered.
7. Open the email log in admin and confirm statuses.

Do not run this test with real customer data before launch approval.

### Test `application_received`

1. Set `EMAIL_PROVIDER=resend`.
2. Set `RESEND_API_KEY` in the hosting provider.
3. Set `EMAIL_FROM` to a verified sender, for example `TenXPros <hello@tenxpros.com>`.
4. Submit `/apply` with a controlled founder-owned test address.
5. Confirm the inbox receives "TenXPros application received".
6. Confirm the admin email log records the event.

### Test accepted/payment-link email

1. Open the test application in `/admin/applications`.
2. Mark it accepted.
3. Confirm a pending payment record is created.
4. Confirm the recipient receives "TenXPros application accepted".
5. Confirm the email body contains the correct manual Stripe Payment Link for the applicant’s tier.
6. Do not mark enrolled until the payment workflow is intentionally tested.

### Verify `EMAIL_FROM`

Before public launch:

- Send to at least one Gmail inbox and one non-Gmail inbox if possible.
- Confirm the display name is `TenXPros`.
- Confirm the sender domain matches the verified domain.
- Confirm replies go to the intended monitored inbox if replies are enabled.

## 6. Before Launch

- [ ] Resend domain verified.
- [ ] SPF/DKIM/DMARC confirmed.
- [ ] `EMAIL_PROVIDER=resend`.
- [ ] `RESEND_API_KEY` configured in hosting secrets.
- [ ] `EMAIL_FROM` uses a verified domain.
- [ ] Test email delivered to at least one external inbox.
- [ ] Console/dev mode disabled in production.

## 7. If Email Remains In Console/Dev Mode

If `EMAIL_PROVIDER=console`, emails are not delivered to applicants or participants. That is acceptable for local acceptance only.

Before public launch:

1. Stop launch.
2. Configure Resend.
3. Rerun `npm run launch:env-check`.
4. Repeat the email test flow.

Keep console mode for local development by setting:

```bash
EMAIL_PROVIDER=console
EMAIL_FROM="TenXPros <hello@tenxpros.test>"
```

Never use console mode for public launch.
