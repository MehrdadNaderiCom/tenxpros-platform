### Full migration SQL summary
```
CREATE TYPE "PaymentMethod" AS ENUM ('WISE','STRIPE','MANUAL_INVOICE','BANK_TRANSFER','OTHER');
ALTER TYPE "PaymentStatus" ADD VALUE 'INSTRUCTIONS_SENT';
ALTER TYPE "PaymentStatus" ADD VALUE 'WAIVED';
ALTER TYPE "PaymentStatus" ADD VALUE 'CANCELLED';
ALTER TABLE "PricingTier"  ADD COLUMN paymentCurrency TEXT, paymentDueDays INTEGER,
                                      paymentInstructions TEXT, paymentLink TEXT, paymentMethod "PaymentMethod";
ALTER TABLE "PaymentRecord" ADD COLUMN cancelledAt TIMESTAMP(3), discountNote TEXT, dueAt TIMESTAMP(3),
                                      instructionsSentAt TIMESTAMP(3), internalNote TEXT, method "PaymentMethod",
                                      paymentInstructions TEXT, paymentLink TEXT,
                                      showDiscountNoteToApplicant BOOLEAN NOT NULL DEFAULT false, waivedAt TIMESTAMP(3);
```
It only: creates `PaymentMethod`; adds values to `PaymentStatus`; adds columns to `PricingTier`; adds columns to `PaymentRecord`.

## 3. PostgreSQL version
Production DB **`16.11`** (read-only `SHOW server_version`). PG ≥ 12 supports adding multiple enum values in a single migration, so Prisma's "PostgreSQL ≤ 11" caveat does **not** apply. The migration only *adds* the new enum values (it does not *use* them), so there's no same-transaction-usage concern either.

## 4. Migration risk assessment
- **Low / additive.** All column additions are nullable, except `showDiscountNoteToApplicant BOOLEAN NOT NULL DEFAULT false` whose default backfills existing rows safely. No backfill scripts, no data transforms.
- **Reversibility:** column additions and the new enum are reversible (`DROP COLUMN` / `DROP TYPE`). The three `PaymentStatus` `ADD VALUE` additions are **effectively forward-only** (Postgres can't drop an enum value without recreating the type) — standard behavior; not a concern for an additive launch.
- No impact on existing queries: no current code reads the new fields yet (verified by typecheck/build passing against the regenerated client).
